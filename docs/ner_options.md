# NER 召回层选型 — docs/ner_options.md

> 结论先行：**v0.1 默认不带 NER**。实测（2026-09-27，内置 14 篇语料）jieba 人名识别让
> PERSON 召回保持 1.000 但 P 从 1.000 掉到 0.700（micro P 0.885）——"温馨提示、张江路、
> 红星路、双肩包"都被 jieba 的 nr 词性当成人名。精确优先是我们的产品立场：
> 脱敏场景里误报（错误脱敏破坏可用性）比漏报代价更高。需要补召回时显式 `jieba=True`，
> 数字见 benchmarks/results.md 第三行。

## 候选对比（2026-09-27 核查）

| 方案 | 许可 | 体积 | 人名质量 | 结论 |
|---|---|---|---|---|
| **无 NER（现状默认）** | — | 0 | 上下文 cue：P 1.000 / R 0.917* | 默认。cue 覆盖不到的召回缺口交给 LLM 兜底 |
| **jieba 0.42.1** | MIT | ~19MB（含词典，纯 Python） | P 0.700 / R 1.000（实测） | 可选启用（`pip install helan[jieba]` + `jieba=True`）。注意：项目 2024-08 起未更新 |
| LAC（百度） | Apache-2.0 | 需 paddlepaddle（数百 MB 起） | 比 jieba 好（深度学习） | **不内置**：拖 paddle 违背"零必装依赖、CPU 轻量"定位；确有需要可经 LLM recognizer 路线替代 |
| HanLP 2.x | Apache-2.0（代码） | 需下载预训练模型（100MB+） | 好 | 同上，重；且 RESTful 服务形态与库定位不符 |
| LTP 4.x | **仅免费商用需授权/开源混合**（哈工大讯飞实验室，详见官网） | 模型数十 MB | 好 | 许可复杂度是硬伤，不内置 |
| LLM recognizer（内置） | — | 0（调 API） | 最强（语义级） | 可选，需 API key；偏移对齐安全阀保证不引用原文即丢弃 |

\* R 0.917 为 48 gold 中的 1 个非 cue 人名（散文体叙述内嵌名），诚实记录。

## 决策

1. 默认关闭 NER，保持 P=1.000 的承诺；
2. jieba 作为 opt-in 可选依赖保留（MIT 许可无风险）；
3. 语义级召回缺口统一走 LLM recognizer（偏移安全阀保证可信）；
4. LAC/HanLP/LTP 不内置——体积、许可、部署形态都与"零依赖标准件"冲突。
   未来若做 `helan[ner]` extra，再评估。
